### Security

- Flight SQL bulk ingest and early statement refusals now write an audit record (#887, #882)

    A `DoPut` bulk ingest (`CommandStatementIngest`, what ADBC `adbc_ingest` and dbt seeds send) wrote rows to Iceberg with no audit record. It now writes one record per call, success or failure: actor, target table, ingest mode (`if_not_exist` / `if_exists`), rows written, outcome and the snapshot property keys (never their values). A statement refused by the size limit (`query.max_sql_bytes`) or by admission (per-user concurrency or memory budget) also wrote no record; each now writes one failure record. The oversized one is not parsed: it is recorded as `statement_type` `unknown` with its first KiB of text (never cut inside a string literal) and its full length in `text_len`. The same holds for oversized statements arriving through Flight SQL `GetFlightInfo` and prepared statements. Only the refusal for a closed audit log (`fail_mode = "closed"`) still writes none, since the log is unavailable.
