**STATUS 2026-10-07 (bz): writes read the target through the row-filter guard (`fix/dml-row-filter-error-oracle`, #805).** DELETE and UPDATE evaluate the user's WHERE / SET over a policy relation that projects every column as `CASE WHEN <row filter> THEN <mask or col> END`, plus the row filter's TRUE-only verdict on the stored values (`__pol_admit_<nonce>`) and, for UPDATE, a raw alias per column so unchanged and hidden rows are written back as stored. A row filter alone stays inline; masks still go through the mask-context view. MERGE's target relation does the same, and `raw_target_col` returns the raw alias for every column under a row filter. The DELETE / match evaluators coerce a NULL verdict to FALSE: a row whose WHERE or row filter is NULL is no longer deleted by copy-on-write DELETE. User SQL naming a `__pol_` alias is refused. Always on for writes: the scratch table has no scan pruning to lose. **Open:** remaining items tracked in #805.
