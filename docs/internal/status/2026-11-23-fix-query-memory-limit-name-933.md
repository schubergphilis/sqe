**STATUS 2026-11-23: a statement over its own `query.max_query_memory` fails as `EXCEEDED_QUERY_MEMORY_LIMIT` (`fix/query-memory-limit-name-933`, #933).**

New `SqeErrorCode::ExceededQueryMemoryLimit` (name `EXCEEDED_QUERY_MEMORY_LIMIT`, `INSUFFICIENT_RESOURCES`, numeric 65538). `query_memory::execution_error` picks it when the refusal names the normal quota (`is_query_memory_limit`); the pressure quota and a shared-pool refusal stay `RESOURCE_EXHAUSTED`. Flight maps it to `FAILED_PRECONDITION`; the Trino endpoint sends no `Retry-After` (it answers failed statements with HTTP 200 and the error in the body, and `Retry-After: 1` only for the name `RESOURCE_EXHAUSTED`). Direct `DataFusionError` conversion in `sqe-core`, the buffered result cap, EXPLAIN ANALYZE, the sort-on-write gate and the Hive insert use the same name. `per_user_memory_budget` is unchanged (config validation keeps it at or above `max_query_memory`). Left as is: `max_result_rows` and the spill cap stay `RESOURCE_EXHAUSTED`; worker-side `WorkerResourceExhausted` (workers only scan). The `it` suite was not run (`join_fallback_e2e` assertion updated by hand).
