**STATUS 2026-10-08 (ch): Hive scans plan without reading data files (`fix/hive-plan-time-footer-reads`, #807).** DataFusion 55 removed the per-table `with_collect_stat` opt-out, so with the session default `collect_statistics = true` every `ListingTable::scan` behind a Hive table read each listed file's footer while planning: 1,000 GETs before the first row of a 1,000-file table. Every Hive scan now plans on a copy of the session with the knob off (`without_footer_statistics`; indexed, lazy-limit and unindexed paths); the `read_parquet` family keeps the session as it is. Nothing used those reads: `HiveTableProvider::statistics` answers the logical planner from the manifest, and the scan's physical `num_rows` was `Absent` with the reads as well as without. Local, 1,000 one-row files: planning went from 252 ms with 1,000 data-file reads to 33 ms with 0. `crates/sqe-catalog/tests/it/hive_plan_io_test.rs` counts data-file reads on the session's store while planning and failed before the fix (10 and 4 reads). Left out: the ETag-keyed schema cache from the issue.
