**STATUS 2026-09-20 (bl): the MCP listener has a request deadline, a graceful shutdown and a supervised certificate reloader (`fix/mcp-listener-timeout-shutdown`, #679).** Fifth of the MCP security batch. `mcp_router` wraps the routes in a deadline of `request_timeout_secs` + 15 s (90 s at the default; off when the statement deadline is 0), answering 504 with a JSON-RPC error, so the token check, the metadata fan-out and the encoding are bounded too, not only the statement. `start_mcp_server` takes a `CancellationToken` (re-exported from tokio-util): SIGTERM/SIGINT cancel it, `axum::serve` drains via `with_graceful_shutdown`, the TLS branch via `axum_server::Handle::graceful_shutdown(30 s)`, `supervise_listener` logs that exit at INFO instead of ERROR, and `watch_mcp_listener` no longer exits 70 for a drained listener. The `spawn_cert_reload_watch` handle was dropped; a watcher now logs at ERROR if the reloader ends or panics while the server is up. The global semaphore half of #678 is not here: !1083 (one metadata admission per tool call) covers the rate-limiter collision, and a process-wide probe bound is its own item. Tests: `watch_mcp_listener_does_not_exit_when_the_listener_closed_on_shutdown`; the it call site updated. Verified: sqe-server mcp tests, clippy on coordinator and server.
