**STATUS 2026-09-19 (bf): Hive listings are process-wide per catalog, so an MCP tool call no longer re-lists Glue (`perf/hive-shared-listings`).** Work package 2 item 1. `HiveListings` lived on the session's `HiveCatalogProvider`, and an MCP tool call is a session of its own, so every `describe_schema` and every page of `search_tables` paid one `GetTables` per database it touched regardless of how fresh the previous call's snapshot was (135 schemas = 135 listings per call). The snapshots now live in `HiveMetadataCache` keyed by catalog name (`listings_for`), shared by every session's provider; a Hive listing is not principal-filtered and the `caller` gate runs at table load, so nothing about authorization moved. `invalidate`, `invalidate_database` and `invalidate_all` on the cache drop the listing too, which is what keeps a session's own `CREATE EXTERNAL TABLE` / `DROP TABLE` visible now that a fresh provider no longer means an empty snapshot; the coordinator passed a hard-coded 60 s as the listing TTL and now passes `[hive] metadata_ttl_secs`, whose default moves from 60 to 600 (Glue has no change token cheaper than the fetch, so keying the entry by `VersionId` would cost the `GetTable` it exists to avoid; an unchanged refetch already keeps the file facts).
