**STATUS 2026-09-16 (am): MCP `describe_schema`, one call per schema for the crawler (`feat/mcp-describe-schema`).** The sqe-semantic sidecar crawled a 40-table Glue database in ~70 s because it made three metadata calls per table plus a profile statement over MCP. The new tool describes every table and view in a schema in one call, composed of the statements the single-table tools issue so it is never looser than they are: `SHOW TABLES` (visibility-filtered; the Iceberg branch now also lists REST views, as Trino does), `SHOW COLUMNS FROM` per table (the policy path `describe_table` uses), `SHOW STATS FOR` when `include_stats` (snapshot summary, or for a Hive root the manifest's `numRows`/`recordCount`/`totalSize`, new: `SHOW STATS` used to fail on Hive tables), `EXPLAIN SELECT * .. LIMIT 1` when `include_queryability` (planning only), and one `information_schema.tables` read per call for table-vs-view (best effort). Bounded concurrency (8), per-table errors recorded on the entry (`error` / `stats_error` / `queryability_error`) rather than failing the call, pages by table name (200 default, 500 cap) with the byte cap shortening a page and `next_page_token` pointing at the first table dropped. `SHOW COLUMNS` / `DESCRIBE` gained a `comment` column (Glue column comment; Iceberg `doc` via a cached load) for both tools. `SHOW STATS FOR` now splits quoted names, so `get_table_stats` works on `"cat"."schema"."t"`. Not included: table `properties`, column-level statistics, `snapshot_id` (always null). Verified: 4 new sqe-mcp tests (pagination, error isolation, kind/stats/plan fields, describe_table parity on the same statement), sqe-mcp and coordinator clippy, `cargo check --locked --no-default-features --bin sqe-server`; integration test `mcp_describe_schema_e2e` for `make test-integration FILTER=mcp_describe_schema`. Timing on the live Glue database needs the user's server restarted on this build.
