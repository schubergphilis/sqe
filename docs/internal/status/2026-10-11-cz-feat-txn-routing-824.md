**STATUS 2026-10-11 (cz): transaction routing and the session lifecycle (`feat/txn-routing-824`, #824).** Before this change, a replayed transaction id reaching a coordinator that did not know it (another replica, or the same one after a restart) started a fresh, empty transaction, and `COMMIT` succeeded with nothing to publish. Ids now carry a per-process incarnation in their top 32 bits (`sqe_core::txn_id`; still a v4 UUID, so branch names are unchanged). `TxnRegistry` refuses a foreign id with `TRANSACTION_CONFLICT` "not found on this coordinator" on every statement and on `COMMIT`; `ROLLBACK` of it succeeds so a Trino client can clear the id. We chose a deterministic error over proxying. A session leaving `SessionManager` (cap eviction, token expiry, idle sweep, close) rolls back its Flight transaction through a new `on_session_end` hook, and `shutdown_with_drain` takes a `before_close` future that rolls back every open transaction (bounded at 10 s). New metrics: `sqe_transactions_open`, `sqe_transactions_ended_total{outcome}`, `sqe_transaction_duration_seconds`, `sqe_transaction_not_found_total`, `sqe_transaction_branch_drop_failures_total`. Book: a Transactions section in `dml.md`, the Trino limitation bullet, the Kubernetes single-replica note, the metrics table. Tests: txn_id (2), txn_registry (foreign id, session end, shutdown), session-end hook, Trino transaction tests. **Known gap, documented:** a Flight SQL transaction lives on the server session, so once that session ends the client's next request gets a fresh session and autocommits with no error. Closing it needs the Flight `BeginTransaction` action with a client-carried id. **Not done:** the sweep of `sqe-txn-` branches a crashed coordinator leaves behind (#824 criterion 2; `maintenance_scheduler`, active mode only, age threshold well above the 30-minute idle timeout). **NEXT:** the orphan branch sweep, then Flight `BeginTransaction` / `EndTransaction`.
