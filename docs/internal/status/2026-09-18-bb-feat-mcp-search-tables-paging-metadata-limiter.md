**STATUS 2026-09-18 (bb): `search_tables` pages, reports what it skipped, and one metadata tool call is one rate-limit charge (`feat/mcp-search-tables-paging-metadata-limiter`, #699).** Over the Glue root a search for `%` matched 697 tables, returned 200 with no way to the rest, and every one of its 135 `SHOW TABLES` was charged to `per_user_queries_per_minute` (120), so the tail was skipped at DEBUG and the agent saw a listing that looked complete; the quickstart had raised the limit to 1000 to get around it. Now: `QueryExecutor` has two lanes, `execute` (statements the caller asked for, query limiter) and `execute_metadata` (the `SHOW`s a tool issues, not charged) plus `admit_metadata_call` (one `MetadataRateLimiter` charge per metadata tool call, `metadata_per_user_per_minute`, 120 default); the coordinator executor implements both and `mcp_router` / `start_mcp_server` take the metadata limiter. `search_tables` pages by `(schema, table)` like `describe_schema` (`page_size` default 200, max 500, `next_page_token`), keeps `total_rows`, and returns `skipped_schemas: [{schema, reason}]` for a schema that failed to list or sat beyond the 200-schema walk cap. Tests: paging over the scripted fixture with the token round trip and a rejected token; 135 schemas through `call_tool` = one admission, zero query-lane charges, 271 metadata statements. The configuration reference says which knob covers which path. The quickstart's 1000/min workaround goes back to the default in !1078 once this merges.
