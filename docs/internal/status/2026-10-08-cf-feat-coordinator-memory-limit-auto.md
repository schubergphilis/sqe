**STATUS 2026-10-08 (cf): coordinator `memory_limit = "auto"` and the headroom check (`feat/coordinator-memory-limit-auto`, #808).** `coordinator.memory_limit = "auto"` sizes the pool from the enforced cgroup limit: limit x `memory_limit_auto_fraction` (default 0.7) minus the new `coordinator.process_headroom`. With no enforced limit it resolves to the old 8GB default. The resolved byte count is written back into the config before anything reads it, so the runtime, admission gate, write path and maintenance runtime all see one value. Like the worker, the coordinator now refuses to start when `memory_limit + process_headroom` exceeds the enforced limit, and it runs the runtime memory watch. Both roles share one check, `sqe_core::check_process_headroom`. An explicit size behaves as before. The Helm chart's coordinator (1500MB pool in a 2Gi pod) would fail that check with the 2GB default headroom, so the chart now renders `process_headroom = "512MB"` (2012MB < 2Gi). Worker values (6GB in 8Gi) pass unchanged.
