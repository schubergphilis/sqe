**STATUS 2026-10-09 (cq): OpenLineage events name the Iceberg catalog, the written columns and the committed snapshot (`fix/openlineage-portal-gaps`).** A lineage consumer saw one table under two identities. A scan was named `sqe://default` (a literal fallback), and the written table was named by the bare Polaris URL. Neither name carried the catalog. Every dataset is now namespace `sqe://<catalog>` and name `<schema>.<table>`, with an OL `symlinks` TABLE identifier `<catalog.schema.table>` under the catalog URI. A REST catalog is named after its warehouse, so the legacy `iceberg` block and a `polaris-auto` catalog no longer give two names. Unqualified and 2-part scans resolve in the statement's session scope. A write is labelled with the catalog it resolves against (the qualifier, then the session catalog, then the configured default), not always the default. The output fields of INSERT and DML are named after the target table's columns by position, not the SELECT expressions. DROP, CREATE, CTAS, CREATE OR REPLACE, INSERT OVERWRITE and TRUNCATE carry `lifecycleStateChange`. An INSERT append or CTAS carries the committed snapshot as the `version` facet. Every event carries the run facet `sqe_query: {"queryId": <runId>}`. A Trino statement now runs under the protocol query id, so `runId`, query history and audit records match the id the client polls. Flight SQL, Quack and MCP still mint a fresh UUIDv7. There is no flag: the namespace and field-name changes apply to every lineage event. Golden tests in `sqe-lineage/tests/it/portal_gaps_test.rs` replay recorded statements and pin the whole event JSON. Open: INSERT OVERWRITE, CREATE OR REPLACE in place, MERGE, UPDATE, DELETE and an empty write carry no snapshot version.
