**STATUS 2026-10-11 (da): sweep of transaction branches a crashed coordinator left behind (`feat/txn-orphan-branch-sweep`, #824 criterion 2, openspec 4.4 / 4.5).** A crash leaves `sqe-txn-<id>` branches whose staged files nothing removes. A branch cannot be judged dead by asking coordinators, so the registry now caps a transaction at 24 hours however busy (`sqe_catalog::txn::MAX_LIFETIME`, new outcome label `lifetime`). A branch whose head is a snapshot only transaction refs reach, written more than 25 hours ago (cap plus an hour of clock skew), is therefore dead: `txn::stale_txn_refs`. `txn::drop_stale_branches` drops them in one commit. `CALL system.expire_snapshots` runs it first (best-effort; `detail` reports `txn_branches_dropped`), so the branch snapshots expire in the same call and `remove_orphan_files` deletes their files. The maintenance scheduler in Active mode runs it for opted-in tables whose discovery load found stale refs, as a permit-free job like the history retention pass. Iceberg's `max-ref-age-ms` was not usable: every branch write resets the ref retention. Branches still at their base snapshot carry `main`'s timestamp and are left for `ALTER TABLE ... DROP BRANCH`. Dropping a live branch loses no data: `COMMIT` fails with `TRANSACTION_CONFLICT`. 4.5 verified by reading: orphan-file cleanup walks every snapshot, branch ones included. Tests: `stale_txn_refs` unit test, registry lifetime test, sqlite-rig sweep test (now vs two days on, then COMMIT aborts). **NEXT:** Flight `BeginTransaction` / `EndTransaction` (openspec 5.1 / 5.2).
