**STATUS 2026-10-07 (bx): catalog-vended, table-scoped S3 credentials (`feat/polaris-vended-credentials`).** SQE now sends `X-Iceberg-Access-Delegation: vended-credentials` when `[catalog] access_delegation = "vended-credentials"` or `require_vended_credentials` is set. The vendored REST client lets the table's vended keys beat the static `[storage]` pair, picking the `storage-credentials` entry with the longest matching prefix and falling back to `config` (vendor patch, marked `SQE PATCH (vended-credentials)`). The table metadata cache, stored prepared plans and distributed fragments all honour `s3.session-token-expires-at-ms`. The refresh-task stub is gone: it reloads the table as the querying user and pushes the new set to workers. `distributed_credentials = "vended"` ships the table's set, including the token, and never the engine key. Verified against the local Polaris 1.7 stack with static keys blanked (`vended_only_ctas_insert_select_roundtrip`, `needs:polaris`). **NEXT:** an e2e that lets a token expire mid-scan on the two-worker rig; an STS-backed quickstart (Polaris `stsEndpoint` to an emulator) with no static key; and calling the catalog's `client.refresh-credentials-endpoint` instead of a full reload. File TVFs, Hive and distributed compaction still use the static pair (documented in `s3vending.md`).
