**STATUS 2026-09-16 (ak): Glue always compiled into `sqe-server` (`feat/glue-default-in-server`).** The Glue Hive root was an opt-in cargo feature, and every shipping build site (`release-binaries`, the Dockerfile, `scripts/build.sh`) passes `--no-default-features`, so a stock release binary or image refused `--glue-catalog` while the local dev build accepted it. `sqe-server` now enables `sqe-coordinator/glue` on the dependency itself, so the flag-less builds carry it (`cargo tree --no-default-features -i aws-sdk-glue` shows it reachable from the binary); the `glue` feature stays as a no-op alias. HMS/JDBC stay behind `CATALOG_FEATURES=sqe-catalog/full-backends`. Docs (mcp-server getting-started, production guide) updated. Follow-ups from the same production-design conversation, both unscheduled: SQE ignores Ranger policyType-0 access policies, so without Polaris there is no table-level allow/deny for Hive roots (a `false` row filter is the only deny); and the MCP door drops the peer address before the query span (`client_ip: None` on every MCP query, no `X-Forwarded-For` either).
