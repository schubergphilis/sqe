**STATUS 2026-10-10 (cx): single-table transactions on a per-transaction branch (`feat/txn-branch-821`, #821 + #822).** Inside `START TRANSACTION`, INSERT / UPDATE / DELETE / MERGE / TRUNCATE now run. The first write creates the branch `sqe-txn-<id>` at `main`, every write commits to it, and the session catalog loads the table pinned to the branch head (`Table::pinned_to_ref`, matched by table UUID), so later statements and the scans inside DML see the transaction's writes (#822) with no new scan code. `COMMIT` runs the new vendored `PublishBranchAction`: one catalog commit that moves `main` to the branch head and drops the branch, requiring `main` to still be at the base. If it moved, `COMMIT` fails with the new `TransactionConflict` (Trino code 17, gRPC `Aborted`), the branch is dropped and the transaction ends; any other publish failure keeps it open. `ROLLBACK` and a 30-minute idle sweep drop the branch; the added files are left to orphan cleanup. Transaction state lives in `TxnRegistry` (UUID ids, owner-bound, 24-hour tombstones for ended ids) and a task-local `TxnScope`. In-flight branches are hidden from SQE: time travel by name or by a branch-private snapshot id, incremental reads, ref DDL and `SET WRITE_BRANCH` refuse them, and `$snapshots` / `$refs` leave them out. One table per transaction (#823), refused before any file is written; DDL, CTAS, Hive writes, Flight ingest and write-branch sessions stay refused. Over Trino, `COMMIT` / `ROLLBACK` go to the executor and the clear header goes out only on success.
