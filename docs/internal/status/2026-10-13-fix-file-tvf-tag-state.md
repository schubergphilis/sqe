**STATUS 2026-10-13: file table functions are not denied for an unknown tag state (`fix/file-tvf-tag-state`).**

With the Ranger engine and a tag source, `read_csv` / `read_parquet` / `read_json` returned the file's schema and 0 rows, and a CTAS over them created an empty table: the rewriter governed the TVF scan (`read_csv()`, qualified with the session catalog) as a table, `CacheTagSource` had no entry for it, and the unknown-tag-state arm injected `lit(false)`. `PreparedProviders::insert`, which every file reader goes through, now wraps the provider in `FileTableProvider` (delegating, read-only). The rewriter takes an injected `with_file_table(is_file_table_provider)` and treats such scans as known-no-tags, like the reserved virtual schemas. Detection is by provider type; a scan name shared with a non-file scan in the same plan is governed as a table. Metadata TVFs keep the #750 target check. Tested: the sqe-policy unit test (fails without the exemption), and `access_control_e2e::file_table_function_is_not_denied_for_unknown_tag_state` on a cold handler (count 3, outside path refused, a table still denied).
