**STATUS 2026-10-09 (cm): nested Trino types send nested `typeSignature`s (`fix/trino-nested-type-signature`, #818).** `type_signature_for` passed `array(...)`, `map(...)` and `row(...)` through as a parameterized `rawType`. The JDBC driver's `ClientTypeSignature` rejects a `rawType` holding `,`, `<` or `>`, so map and row columns failed the whole response, the same failure class as #345. Now these types follow Trino's own client shapes: `array` has one `TYPE` argument and `map` has two. `row` has one `NAMED_TYPE` argument per field: a name (`fieldName.name`, with quoted names unescaped and `null` for anonymous fields) plus the field's own signature. Parameters at any depth, such as decimal or `timestamp(p) with time zone`, stay in `arguments`. Other integer-parameterized types split the same way (`varchar(255)` becomes `varchar` plus `LONG 255`). Malformed strings still pass through unchanged. Two property tests cover it: generated trees up to depth 4 in `sqe-trino-protocol`, and every nested Arrow type the server emits in `sqe-trino-compat`. Both require that no `rawType` at any depth holds a parameter. The signature fix alone left JDBC failing on fetch ("Unexpected token VALUE_STRING"), because nested values went out as Arrow's display string. `arrow_value_to_json` now encodes them as Trino does, recursively: lists as JSON arrays, maps as objects, structs as arrays of field values, with null at any depth. `arrow_to_trino_type` quotes a row field name that is not a plain lowercase identifier (`row("My Field" varchar)`). A property test checks that any such name round-trips as `fieldName.name`. The wire golden `nested_types.json` runs the real server, and trino-jdbc 483 reads all four of its columns (array, map, row and an array of rows) through a mock serving that golden. sqe-mcp's `batches_json` now cuts an oversized array, map or row as its JSON text, the way it cuts a long string, so a huge nested cell no longer empties the page (`fix/mcp-nested-cell-truncation`). **Open:** a live-stack tempto run.
