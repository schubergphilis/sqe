**STATUS 2026-10-07 (cb): recursive CTEs keep every iteration's MIN/MAX (`fix/recursive-cte-aggregate-dynamic-filter`, apache/datafusion#26054).** DataFusion's `RecursiveQueryExec` resets the recursive term between iterations, but `AggregateExec` keeps the MIN/MAX dynamic filter the first iteration pushed into its scan, so later iterations scanned with a stale bound and returned NULL or wrong rows (SQE's defaults enable the pushdown). User contexts (coordinator, `sqe-cli` embedded, Hive view planning) are now built by `sqe_catalog::engine_context`, whose `EngineQueryPlanner` plans a plan holding `WITH RECURSIVE` without `enable_aggregate_dynamic_filter_pushdown`; every other plan is unchanged. The tripwire test `plain_datafusion_still_loses_later_iterations` fails once DataFusion fixes #26054; then drop the planner.
