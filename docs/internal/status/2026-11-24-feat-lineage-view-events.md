**STATUS 2026-11-24: CREATE VIEW and DROP VIEW emit lineage for the view (`feat/lineage-view-events`).**

`handle_create_view` keeps the planned body from `get_schema_with_plan` and records it under a DataFusion `CreateView` named after the view (`lineage_view_plan`), so the extractor gives the view's inputs, schema and column lineage; `lineage_output_lifecycle` stamps `CREATE`, or `OVERWRITE` for OR REPLACE. DROP VIEW records `LineageHint::ViewLifecycle` with `DROP` for the first name, before the drop, as DROP TABLE does. Both outputs carry the OpenLineage `datasetType: VIEW` facet (`DatasetTypeFacet`). The body is traced as written, without the policy rewrite: a view stores its definition, so no masking record is attached. Because the captured plan also feeds audit resources and the query tracker, CREATE VIEW's audit entry now lists the base tables its body reads. Tests: `create_view_emits_the_view_with_its_inputs_and_dataset_type_view` and `drop_view_emits_the_view_with_lifecycle_drop_and_dataset_type_view` (sqe-lineage IT, wire JSON), and the CREATE / OR REPLACE VIEW cases in `output_lifecycle_is_decided_from_the_statement`, all seen failing first. Not run: `make test-integration`.

**NEXT:** ALTER VIEW ... RENAME TO lineage is a separate feature item: SQE does not rename views today, so it needs view rename through the Iceberg REST views API (`/v1/{prefix}/views/rename`) first, then a `RENAME` lifecycle event with `previousIdentifier` and `datasetType: VIEW`.
