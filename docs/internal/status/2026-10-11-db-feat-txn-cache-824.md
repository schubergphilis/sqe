**STATUS 2026-10-11 (db): a write inside a transaction leaves other users' caches alone (`feat/txn-cache-824`, #824, openspec 2.4).** A branch write evicted the table from every user's metadata cache and dropped matching result-cache entries, although `main` had not moved. The result cache is now skipped for writes inside a transaction (`COMMIT` already clears it when the branch is published), and the metadata cache is evicted for the writer's token only, in `SessionCatalogBridge::update_table` and `WriteHandler::after_commit`. The writer's own copy still has to go: `pin_to_txn_branch` reloads only a copy without the branch ref, so the next statement must miss. The session-context drop at `COMMIT` stays user-wide because that cache key has no session id. Tests: `after_commit_inside_a_transaction_evicts_only_the_writer`, and the sqlite-rig transaction tests (commit, read-your-writes, conflict, empty table) still pass. **Known bug, not fixed here:** Flight SQL sessions are keyed by bearer fingerprint, so two clients sharing one token share a session and a SQL `BEGIN`: one client's `BEGIN` puts the other's writes in its transaction. The Flight `BeginTransaction` RPC (`feat/txn-flight-rpc`) carries the id per client and avoids it. **NEXT:** OCSF begin / commit / rollback events and lineage at `COMMIT` (openspec 6.1).
