**STATUS 2026-10-11 (dc): audit and lineage for transactions (`feat/txn-audit-824`, #824, openspec 6.1).** `TxnRegistry` writes an `AuditKind::Transaction` record (OCSF 6005, details under `unmapped.transaction`) when a transaction's first statement runs and one when it ends, from `record_end`, so every outcome is covered: `committed`, `conflict` (failure, `TRANSACTION_CONFLICT`), `rolled_back`, `session_ended`, `idle_timeout`, `lifetime`, `shutdown`. The end record carries the duration and the `main` snapshot id `COMMIT` published per table (`TxnScope::published`). Lineage: a write inside a transaction emits START when it runs and holds its COMPLETE until the end (`TxnRegistry::at_end`); anything but a commit turns it into FAIL `transaction not committed (<reason>)`, so lineage never shows a write `main` never saw. BEGIN / COMMIT / ROLLBACK / SET TRANSACTION emit no runs. INSERT's lineage version inside a transaction was `main`'s snapshot; it is now the branch head, which `COMMIT` fast-forwards `main` to. Limits: actor is the username only; a transaction that runs no statement writes no record. **NEXT:** dbt-sqe per-connection transactions (openspec 5.4); then token refresh-ahead (#816) and re-resolve on 401 (#803).
