**STATUS 2026-09-20 (bi): MCP withholds system error text from the model (`fix/mcp-error-redaction`, #675).** Second of the MCP security batch. `call_tool`, the `list_catalogs` probes and the `describe_schema` per-table probe returned `error.to_string()`: object-store and catalog errors carry bucket names, object keys, hostnames and region or account hints, and an agent transcript is a leaky place for those. `client_error_text` now decides by `SqeErrorCode`: a user error (syntax, not-found, denial, not-supported, cancelled) goes through verbatim as on Flight and Trino; a system error becomes the code's `generic_message` plus an `error_id`, and the full text is logged at WARN under that id. Two system texts stay verbatim because the hint is the fix: the Arrow decimal overflow (value and precision only) and a rate-limit denial (retry-after). `list_catalogs` still classifies `auth_error` on the full text, then reports the redacted detail. Root-cause fix alongside in sqe-core: DataFusion's `Schema error: No field named x` was classified `ExecutionFailed`, so a bad column reference read as a system fault on every front door; it is `ColumnNotFound` now. Docs: deployment/mcp.md "Error text" section, tool description. Tests: `system_error_text_is_withheld_from_the_client_and_user_errors_are_not`, `error_code_column_not_found_from_datafusion_schema_error`, two existing tests updated to the redacted shape.
