**STATUS 2026-10-09 (cp): Ranger policies can be catalog-scoped; mask and row-filter precedence follows Ranger (`feat/policy-catalog-scope`).** `[policy.ranger] catalog-scoped` (default false, env `SQE_POLICY__RANGER__CATALOG_SCOPED`): an Iceberg table's Ranger `database` is `<catalog>.<namespace>`, so several catalogs holding the same `namespace.table` no longer share masks; the last-component fallback is off under it (deny items included), a catalog-less reference is denied, and `CREATE POLICY` needs a 3-part name. The key goes through `resolve_policy_key_scoped` (rewriter, SHOW STATS, SHOW EFFECTIVE POLICY, metadata-TVF gate in the rewriter and the coordinator's metadata-statement gate) driven by `PolicyStore::catalog_scoped`. Precedence (main already took the first matching mask item within a policy): the first mask policy to decide a column is final, MASK_NONE included; `policyPriority` desc then bundle order; first matching row-filter item per policy; an empty filter expression filters nothing; conditional items stay fail-closed. These precedence changes are not behind the flag. `[policy.ranger]` and `[access_control.ranger]` snake keys and env overrides fixed. The DML probe (`extract_write_predicates`: DELETE, UPDATE, MERGE, the INSERT `WITH CHECK` guard and the INSERT OVERWRITE / CREATE OR REPLACE refusal) carries the target catalog, as the read path's `TableScope::qualify` already did. Tests: `ranger_store::catalog_scope_and_precedence_tests` (15 unit tests: scoping, fallback, deny, DDL, first-item and first-policy precedence, MASK_NONE, conditional items, row filters, tag policies); `catalog_scoped_mask_through_the_rewriter_covers_one_catalog` (wiremock Ranger, two catalogs with the same `finance.orders`); `dml_target_policy_is_keyed_on_the_target_catalog` (DELETE, UPDATE, MERGE). Open: Hive grant keys stay `<root>.<database>` under the flag; same-priority `evalOrder` parity; `SHOW EFFECTIVE POLICY FOR USER` resolves another user without their groups.
