**STATUS 2026-09-16 (ao): metadata statements leave the per-user memory budget alone (`fix/admission-metadata-no-memory-reservation`).** The first `describe_schema` run on the release build against a 40-table Glue database returned 36 tables with `Per-user memory budget exceeded ... 1073741824 bytes reserved, limit 1073741824`: the tool runs eight `SHOW COLUMNS` / `SHOW STATS` / `EXPLAIN` statements at once, admission reserved the full 256MB `max_query_memory` for each, and the 1GB `per_user_memory_budget` admits exactly four. Exactly four tables succeeded per run, every run. Admission now classifies the leading keyword before the parse and skips the memory reservation for `SHOW`, `DESCRIBE`/`DESC` and `EXPLAIN` (not `EXPLAIN ANALYZE`, which executes); they still take both concurrency permits. Two unit tests on the classifier; the crawler timing is re-measured on the rebuilt binary.
