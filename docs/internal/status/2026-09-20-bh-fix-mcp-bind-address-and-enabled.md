**STATUS 2026-09-20 (bh): the MCP listener has a bind address, and anonymous mode defaults to loopback (`fix/mcp-bind-address-and-enabled`, #671 #672).** First of the MCP security batch for production. `start_mcp_server` bound `0.0.0.0` unconditionally, so `--mcp-anonymous` on a laptop or bastion was an unauthenticated data endpoint on every interface. New `[mcp] bind_address` and `--mcp-bind <ip>`: empty resolves to `127.0.0.1` under `mode = "anonymous"` and `0.0.0.0` otherwise (`McpConfig::bind_ip`), an address that does not parse fails `validate`, and the server warns when an anonymous endpoint is still network-reachable (explicit non-loopback bind, or `port = 0` on the web listener). #672: `is_enabled()` still honours `port > 0` alone for this release, but `enabled_by_port_only()` drives a startup DEPRECATED warning; the shortcut goes next release.
