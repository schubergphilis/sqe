**STATUS 2026-10-11 (db): Flight SQL `BeginTransaction` / `EndTransaction` (`feat/txn-flight-rpc`, #824 follow-up).** SqlInfo now advertises transactions (8 = Transaction, 11, 563, 564 = READ_COMMITTED, 565/566 false), so ADBC (and any Flight SQL client that calls `BeginTransaction`) opens one whenever autocommit is off, the DB-API default. `BeginTransaction` mints an incarnation-tagged id and registers it for the user; the client sends it on every statement ticket, update, prepared statement and bulk ingest, and `EndTransaction` commits or rolls back. The id rides `Session::with_client_transaction_id`, so `QueryHandler::execute_with_id` runs DDL and CTAS in that transaction as autocommit and leaves it open (a SQL `BEGIN` still refuses them). Ingest runs on the branch instead of being refused. A prepared statement remembers the transaction it was created in. A request id that differs from a SQL `BEGIN` already on the session is `FAILED_PRECONDITION`. Begin / commit / rollback write an audit statement. The client holding the id closes the #824 gap where an ended session silently dropped a Flight transaction. **Behaviour change:** a DB-API client that never calls `commit()` now loses its DML (rolled back after the 30-minute idle timeout). The dlt quickstart sets `autocommit=True`; dbt-sqe already did. Book: `dml.md` Transactions, `connecting.md`. Tests: flight_sql unit tests (ticket carries the id, bad actions, other user, request vs session id, SqlInfo), `test_client_transaction_ddl_autocommits_and_dml_waits` under `make test-integration`.
