**STATUS 2026-10-10 (cv): dbt-sqe sends no BEGIN / COMMIT (`fix/dbt-sqe-autocommit-820`, #820 step 1).** dbt-adapters wraps every model in textual `BEGIN` / `COMMIT`, which SQE accepted as no-ops while each write autocommitted. dbt-sqe now overrides `begin`, `commit`, `add_begin_query` and `add_commit_query` the way dbt-trino does (it keeps the `transaction_open` bookkeeping and sends nothing), and it opens ADBC with `autocommit=True`, so the "Cannot disable autocommit" warning is gone and the handle's `commit()` / `rollback()` are no-ops. This ships before the engine half of #820, which refuses writes inside an explicit transaction: a dbt-sqe without this change would fail on its first model once that lands. Tests: `adapters/dbt-sqe/tests/test_connections.py`. **NEXT:** #820 engine half, with Trino transaction-id headers and the autocommit write guard on Trino and Flight SQL.
