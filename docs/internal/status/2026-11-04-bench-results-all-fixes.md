Findings:

- Decimal rounding: SQE truncates decimal division, `avg(decimal)` and decimal-to-integer casts where Trino and PostgreSQL round half up (probe: `2.00/3.00` = 0.666666, `avg(0.01,0.01,0.00)` = 0.006666, `CAST(7.5 AS INT)` = 7). Behind q31/q36/q54/q59/q61/q83/q90 and TPCx-BB q09. Fix on its own branch.
- Result scale, not rounding: q06/q35/q44 (Trino's `avg(decimal(p,s))` keeps scale s), q58/q78 (Trino's quotient carries fewer digits).
- New at SF10: q27 (`agg1` 56 vs 68) and q75 (`i_manufact_id` 110 vs 152). Check whether each ORDER BY is a total order before calling them ties at the LIMIT.
- TPCx-BB q02 returns 0 rows at SF10 (31 at SF1): store returns are exactly 10% of sales, and q02 keeps classes with a return rate above 0.10. At SF10 the noise is too small to lift any class over. Same family as q64.
- TPCx-BB q01 is the slowest query by far (13 s at SF1, 140-147 s at SF10, 11x for 10x data); its `-- timeout: 120s` header is too tight at SF10.
- TPC-DS q65 at SF10: 0.65 s on 2026-10-05, 3.6 s now. Regression candidate (the store/item dimensions changed with !1639).
- Trino in Docker Desktop (16.5 GiB VM, Polaris/RustFS/engine-bench resident) is killed at SF10: unbounded at TPC-DS q11, `TRINO_MEMORY=8g` at TPCx-BB q05. SF10 comparisons need a bigger VM or a smaller Trino.
