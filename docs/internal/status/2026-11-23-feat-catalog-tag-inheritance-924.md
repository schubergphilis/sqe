**STATUS 2026-11-23: catalog tags inherited behind `policy.inherit_catalog_tags` (`feat/catalog-tag-inheritance-924`, #924, openspec tag-inheritance 2.5-2.8).**

A second flag next to `inherit_schema_tags`, independent of it, default off. With it on a column's effective tags are its own, table's, schema's, then catalog's; the nearest key wins. `sqe.catalog-tags` is read through `SessionCatalog::catalog_properties()` (one Polaris management GET with the caller's token) on every table load, no cache and no memo: a session memo would go stale on `ALTER CATALOG ... UNSET TAGS` because session contexts live across statements. The cost is one GET per table with the flag on. The state is `CatalogTagState` (not inherited, known, unknown), a separate required constructor argument on every Iceberg provider; unknown refuses the read, SHOW STATS and tag-aware writes. A non-Polaris catalog is known and empty. `CacheTagSource` reports unknown with the flag on, the engine-credential read gate and the UPDATE/DELETE/MERGE guards use the same effective tags. The Ranger projection and its load observer stay schema-only: catalog tags are SQE-only, so Spark does not mask on them.

Gaps: a catalog attached at runtime with `ATTACH` has no user token for the Polaris catalog entity and carries no catalog tags. With the flag on every reading principal needs `CATALOG_READ_PROPERTIES` on the Polaris catalog; without it the 403 makes the tag state unknown and reads are refused. Tested live (`catalog_tag_inheritance_reader_needs_catalog_read_properties`: refused, then masked rows after the grant).
