**STATUS 2026-10-26: GEOMETRY / GEOGRAPHY DDL (`feat/geo-ddl-863`, part of #863).**

- **`sqe-sql/src/v3_types.rs`**: `geospatial_type` turns `GEOMETRY[(crs)]` / `GEOGRAPHY[(crs[, algorithm])]` (sqlparser `Custom` types) into the Iceberg type string. SRIDs map as Spark 4.1 + Iceberg 1.12 write them, measured on the Spark container: `GEOMETRY(4326)` -> `geometry` (default `OGC:CRS84`), `GEOMETRY(0)` -> `geometry(SRID:0)`, `GEOMETRY(3857)` -> `geometry(EPSG:3857)`, `GEOGRAPHY(4326)` -> `geography(OGC:CRS84, spherical)`. Spark accepts no algorithm argument; SQE does. `is_v3_only_type` includes them, so the table becomes v3.
- **`sqe-write/src/write_handler.rs`**: `geospatial_iceberg_type` parses that string with iceberg-rust's own `PrimitiveType` deserializer, which validates the CRS, the algorithm and the arity. Arrow storage is `Binary`; `arrow_schema_to_iceberg_with_defaults` sets the Iceberg type on the column. STRUCT / ARRAY / MAP members refuse a geospatial type (it would silently become binary).
- **`sqe-coordinator/src/catalog_ops.rs`**: `ADD COLUMN` sets the geospatial type and refuses it on a v1/v2 table.
- CTAS from a geospatial table already kept the types: the scan tags the columns `geoarrow.wkb` and iceberg-rust's Arrow conversion maps the tag. Now tested.
