**STATUS 2026-10-09 (ck): design for bounding large hash builds (`docs/adaptive-join-fallback-784`, #784).** `docs/internal/specs/2026-10-09-adaptive-join-fallback-design.md`. DataFusion 55.1's hash-join build cannot spill, and Iceberg estimates are off by 3x to 150x, so the planner cannot decide. The design proposes a coordinator retry. A read query that fails with `ResourcesExhausted` before its first output batch is planned again from the same policy-enforced logical plan with `prefer_hash_join = false`, and DataFusion's own planner and `EnforceDistribution` place the sort-merge joins. This avoids the !724 defect class. It retries once, is gated on spill being on, and is behind the proposed `query.join_fallback` setting. The design also covers the exec-wrapper alternative (deferred until the wasted-work metric justifies it), what the fallback plan gives up, and the tests and measurements mapped to #784's acceptance criteria. **NEXT:** review the design, then implement phase 1 on a `feat/` branch.
